# Watch and companion UI review — September 5, 2026

Status: saved for later review. These are proposed improvements, not completed
work or authorization to implement, install, or flash anything.

Keep the black/acid-green identity and the existing Revenant mechanical-skull
artwork. The main opportunities are clearer navigation, accurate previews, and
easier watch controls.

The item numbers below match the UI review conversation. They are separate from
the earlier premium build plan's items 4, 5, and 6.

## Evidence and limits

- Reviewed the live companion home screen, both UI implementations, and the
  watch's compiled artwork.
- Watch findings are code-based, not a fresh on-wrist visual or touch test.
- Remote phone input was paused when the phone switched to another app; the
  entire companion flow was not visually tested.
- No code or settings were changed and nothing was flashed during the review.
- Findings describe the September 5 working tree. Recheck the implementation
  and installed versions before starting a future change.

## Companion app

### 1. Split the long page into Watch, Customize, and Apps

Keep connection status compact. Give the everyday watch overview, appearance
editor, and app integrations clear destinations. Put advanced setup and
recovery under Settings. The current single scrolling page makes basic
customization require substantial scrolling.

### 2. Make previews match the actual watch

The companion's Revenant preview is a simple grid, while the watch uses the
mechanical-skull artwork and a different arrangement of complications. Show
the real layouts, including their actual spacing and typography. Keep sample
values clearly labeled, and represent Large Text accurately.

### 3. Add a persistent Apply changes bar

Clearly distinguish "On your watch," "Unsaved changes," and "Applying."
Keep Apply reachable while editing and show confirmation only for the profile
the watch actually acknowledged.

Currently, editing does not invalidate the previous save-status message, so
"Saved on watch" can remain after further edits. Show validation errors beside
the relevant field, and make it clear when a draft exists only on the phone.
Preserve explicit apply and the separation between draft and confirmed state.

### 4. Use visual customization controls

Use face thumbnails, actual color swatches, and tappable complication slots
instead of relying entirely on dropdowns. Only show complication controls when
the selected layout uses them. Keep controls labeled and accessible.

## Watch

### 5. Put the main action on the first screen

OpenClaw's "Hold to speak" currently sits below the initial viewport. Keep the
speak control and recording feedback together, with cancellation easy to find.
Keep secondary voice settings separate from the primary conversation flow.

For media, prioritize three large transport controls and move secondary
actions into More. Preserve existing capabilities and explicit confirmation
for suggested actions; this is a presentation change, not reduced safeguards.

### 6. Add launcher favorites

There are 17 flat launcher entries, with OpenClaw thirteenth. Put a configurable
handful of everyday apps first, and nest Diagnostics and About under Settings.
Keep all existing routes accessible without giving every route equal prominence.

### 7. Make Context cards tappable

Weather should open Weather, Media should open playback controls, and Inbox
should open notifications. The cards currently display information without
those shortcuts. Preserve vertical scrolling and system edge gestures; a card
tap should navigate, not immediately perform a phone action.

### 8. Standardize touch targets and text layout

Several controls are only 44–52 px tall, below the project's own 56 px minimum.
Some paired rows also exceed their available content width. Correct those
dimensions while preserving the 28 px safe inset, then check long labels,
wrapping, and Large Text throughout the watch UI.

## Suggested first pass

Prioritize items **2, 3, 5, and 8**: faithful previews, clear edit/save feedback,
first-screen primary actions, and reliable touch/layout dimensions. This order
is a recommendation pending review, not an approved implementation plan.

When implementation is requested, verify the changed flows on the actual
phone and watch, including disconnected and pending-save states, normal and
Large Text layouts, and scroll-versus-tap behavior. Build/test results alone do
not establish visual or physical usability.
